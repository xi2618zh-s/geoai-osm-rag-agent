# M09 session state and multi-turn edit evaluation freeze v1

> **English translation.** The authoritative frozen document is the Chinese original [`M09_EVALUATION_FREEZE.md`](M09_EVALUATION_FREEZE.md), which is kept byte for byte as frozen evaluation evidence. This translation is provided for readers and is not part of the frozen evidence; if the two differ, the original applies.

- Frozen: 2026-10-06 (Asia/Shanghai), before any M09 production code.
- Scope: public synthetic offline DatasetRefs and deterministic M07/M08 planning/validation. 16 single-turn edit cases: 4 each for changing the distance, adding an exclusion condition, switching city and requesting a comparison; additional tests for output-format-only changes, version conflicts, isolation between sessions, stale DatasetRefs, no promotion of `partial` results, state limits and rejection of unbounded history. No real models/network/hidden sets, and no inferences about real city coverage.
- Frozen matrix: `benchmarks/data/dev/m09_turn_cases_v1.jsonl`, where each case has `case_id`, `base_class`, `turn`, `expected_action` and `expected_reuse`; it is not rewritten afterwards. Tests use small project-made GeoJSON; city names are only task labels, and a switch/comparison must provide a new source DatasetRef and metadata.
- Metrics: edit recognition and valid state update /16, threshold 16/16; reuse of unaffected upstream steps /4 exclusion cases, threshold 4/4; invalidation of source dependencies on city switch /4, threshold 4/4; comparisons that keep the original baseline and compute only the verified count difference /4, threshold 4/4. Isolation between sessions, rejection of stale versions, recomputation of stale caches and no promotion of `partial` are hard gates.
- Contract: a bounded number of sessions and bounded state fields, with no full chat history or large data entering the context; optimistic concurrency control by version per session; only a successful M08 result can become the current confirmed result. An output-format change reuses the result; an exclusion condition reruns only the added filter and keeps the spatial upstream results with the same inputs/parameters; a distance change recomputes dependent steps and reuses the original data source; a city/source change invalidates by dependency. Every reuse candidate must re-verify the current DatasetRef and output constraints, and reuse can never rest on a model's claim.
- M09 may make a backward-compatible extension to the M07 restricted grammar for "exclusion conditions", which requires an ADR and a byte-level re-check of the old v1/v2 plan evaluations; M08's reusable execution entry point must still run the static gate and result validation. No new dependencies; any change to an old public contract version must record its compatibility impact.
- The M03 Phase 1/2 publications and public evaluation receipts cannot be overwritten; Phase 2 queries remain catalog-informed. GTFS stop buffers do not represent transit isochrones.
