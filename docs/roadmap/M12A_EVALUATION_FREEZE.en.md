## 2. Restricted command grammar (m12a-grammar-v1; honestly called a "restricted command grammar", not open-ended natural-language understanding)

- Normalization: trim leading/trailing whitespace and collapse internal runs of whitespace to a single space; keywords are case-insensitive.
- Production (clauses in fixed order, each optional): `find school coverage gaps` [` farther than ` DIST ` ` UNIT] [` where children aged ` A`-`B ` are at least ` N] [` in ` PLACE]. DIST=`[0-9]+(\.[0-9]+)?`, UNIT=`m|km`, A/B/N=`[0-9]+`, PLACE=`[A-Za-z][A-Za-z -]*`. No match → `unsupported`, reason `command_not_recognized`.
- Slot validation order (the first failure determines the single reason): (1) distance present and its value in metres ≤ 0 or > 2000 → `distance_out_of_range` (missing_fields `[distance]`); (2) age band present and not in {0-4, 5-9, 10-14, 15-19} → `age_band_unsupported` (`[age_band]`, choices in this order); (3) threshold present and < 1 → `threshold_out_of_range` (`[threshold]`); (4) place present and not equal to `lund` after casefolding → `place_not_covered` (`[place]`, choices `[Lund]`); (5) anything missing → `missing_parameters`, with missing_fields listing the missing items in the order distance, age_band, threshold, place. All valid → `plan`.
- Clarification contract `ScenarioClarification` v1.0 (a new contract, not reusing the closed GeoDSL enumeration). Answer format: `ITEM (; ITEM)*`, with ITEM ∈ `distance DIST UNIT`, `age band A-B`, `threshold N`, `place PLACE`; each item may only answer a slot in this clarification's missing_fields, at most once, and the original command must match the clarification record, otherwise `SCENARIO_CLARIFICATION_INVALID`. After completion the slots are validated again by the rules above. Distances are recorded in metres (integer values recorded as int).

## 3. Plan (m12a-plan-v1) and execution

- Tool sequence (when the declared POI CRS ≠ EPSG:3006): `step_1 load_population_dataset(population_grid_raw, provider=scb, dataset_year=2025) → population_grid`; `step_2 reproject_dataset(osm_poi, EPSG:3006) → poi_3006`; `step_3 filter_attributes([amenity eq school], all) → schools`; `step_4 buffer_features(schools, D) → school_service_areas`; `step_5 nearest_features(population_grid → schools, k=1) → grid_nearest_school`; `step_6 filter_attributes([distance_m gt D, left_population_age_<band> gte N], all) → coverage_gaps`. When the declared POI CRS equals EPSG:3006, no reprojection is inserted (5 steps, renumbered). Empty-result policy: steps 1–5 reject (`SCENARIO_EMPTY_UNEXPECTED`), step 6 allows. ≤ 12 steps; tool calls (including internal `validate_geometry`) ≤ 64.
- Binding checks before execution (before any tool call, for every role): the DatasetRef is current with a matching hash, its kind matches the catalogue, the DatasetRef CRS equals the catalogue-declared CRS (otherwise `SCENARIO_CRS_MISMATCH`), and **coordinate plausibility**: the DatasetRef bbox must lie within the declared CRS's area of use (pyproj `area_of_use` converted to that CRS with `transform_bounds`, with each side relaxed by 1% of the width/height) and intersect the study-area BBOX (converted to that CRS); otherwise `SCENARIO_CRS_IMPLAUSIBLE`. When the bbox is unavailable (empty dataset), the plausibility check is skipped and the empty-result policy applies.
- **A wrong CRS must never be reprojected**: on `SCENARIO_CRS_IMPLAUSIBLE`, no analysis tool is called (including `reproject_dataset` and `repair_geometry`). There are only two recoveries: (a) the policy declares a substitute snapshot for this role that passes the same currency/hash/kind/field/plausibility checks → record a successful `alternate_source` → replan once with the substitute snapshot (record `replan_once`) → execute; (b) an explicit call to `reconfirm_source_crs`: the evidence is a specified file entry in a versioned manifest under `data/fixtures/` in the repository (a relative path without `..`), whose `sha256` must equal the DatasetRef content hash and whose top-level `crs` must be a valid EPSG code → the data are re-registered with that CRS as a new DatasetRef (lineage `crs_reconfirmed`, parent ID the original reference, parameter hash the canonical JSON of the evidence), and the catalogue entry for that role is changed to the new reference and the newly declared CRS; otherwise `SCENARIO_CRS_EVIDENCE_INVALID`.
- Every step's output: currency, vector kind, CRS = EPSG:3006, `validate_geometry`, the empty-result policy and the feature cap (policy `max_features` = 10000). Tool exceptions give `SCENARIO_TOOL_FAILED` (with the original error code kept in the finding); a timeout is retried once with identical parameters. At most one replan overall.
- Scoring uses the "invoked analysis tool sequence" (`invoked_tools`) = the analysis tools actually called (excluding internal `validate_geometry`), in call order; the "planned tool sequence" (`planned_tools`) = the plan of the finally executed run before any replanning.

## 4. Report (ScenarioReport v1.0)

- Metric IDs and evidence: `gap_cell_count` (dataset_row_count: coverage_gaps), `gap_children` (dataset_field_sum: coverage_gaps.`left_population_age_<band>`), `total_children` (dataset_field_sum: population_grid.`population_age_<band>`), `gap_children_share` (ratio: gap_children/total_children, omitted when total is 0), `school_count` (dataset_row_count: schools), `grid_cell_count` (dataset_row_count: population_grid), `band_not_reported_cells` (dataset_field_null_count: population_grid.`population_age_<band>`), `distance_threshold_m`, `children_threshold`, `age_band_min`, `age_band_max` (plan_parameter). Report templates must not contain literal numbers.
- `max_gap_distance_m` is neither reported nor scored: edge cells extend at most 1 km beyond the study area and POIs are only extracted up to 3 km outside it, so nearest distances above 2000 m are only upper bounds (the true value is > 2000 m but may be smaller); the table column is named "distance to the nearest school within the extracted area", and the limitations say so.
- Four layers: SCB 1 km grid, schools (OSM), straight-line school buffers (not walking range), coverage gaps; the table lists the gap cells (grid_id, children in the age band, total population, distance, nearest school); downloads are the gap GeoJSON/CSV (an empty result still produces valid empty files).
- Required: data licences and attributions listed separately (SCB CC0-1.0 / Statistics Sweden; OSM ODbL-1.0 / © OpenStreetMap contributors, PBF provider unverified); the population statement (the total covers the cells returned by the WFS, includes edge cells and is not an exact population); the words "restricted command grammar"; limitations (Euclidean distance, not the road network; conservative whole-cell decisions; age band as a proxy; OSM completeness and duplicates; inconsistent data dates; distances above 2000 m are upper bounds). Forbidden: `isochrone`, `walking time`, `travel time`, `natural language understanding`.
- `validate_scenario_report` rebuilds the canonical report, and any deviation raises `SCENARIO_REPORT_EVIDENCE_MISMATCH`; `partial` produces no report. The HTML is self-contained SVG (no external scripts/styles) with 4 layer labels, the two licence attributions and the restricted-command-grammar statement.

- Cases: `benchmarks/data/dev/m12a_scenario_cases_v1.jsonl`, 13 cases (success 2, legal empty 1, clarification 4 (all with completion), unsupported 1, CRS rejection 1, substitute-snapshot recovery 1, trusted-reconfirmation recovery 1, invalid evidence 1, no schools 1). Each case's expected fields are the scoring basis.
- References: `benchmarks/data/dev/m12a_references_v1.json`, generated by `benchmarks/m12a_oracle.py` through `scripts/build_m12a_references.py`, for three parameter sets: `d1000_b5-9_n10` (11 gap cells, 178 gap children, 11,482 children in total), `d1500_b10-14_n10` (7, 97, 12,625), `d2000_b5-9_n20` (0, 0, 11,482); 132 schools, 453 cells, 0 unreported cells for the age band. The minimum margin between a distance threshold and the nearest cell distance is ≥ 0.48 m (no floating-point boundary ambiguity).
- Disclosure: threshold parameters were chosen after looking at the data distribution (an independent geometric computation) and before any system implementation; the oracle and the system share an author, so this is an independent implementation, not independent annotation; this set is public dev, not a hidden test.

## 6. Scoring components and thresholds (all exact)

A case passes only if all components pass; threshold **13/13**:
1. Front-end status, reason, missing_fields, choices; when there is a completion, the status after completion.
2. planned_tools and invoked_tools exact; forbidden_tools appear 0 times among all tool calls (including internal ones).
3. Result status, error code, failing step; the list of recovery events (action, status) and replan_count exact; for C3/C4, the stage-1 error code, the reconfirmation error code, the CRS after reconfirmation and the lineage operation `crs_reconfirmed` (with the rejected reference as parent ID).
4. With a reference: the set of gap grid_ids exact; `gap_cell_count`, `gap_children`, `total_children`, `school_count`, `grid_cell_count` and `band_not_reported_cells` exact integers; `gap_children_share` relative error ≤ 1e-6 (absolute error ≤ 1e-12 when the reference is 0).
5. When a report is expected: `validate_scenario_report` passes; metric values match the reference; licence attributions, population statement and the restricted-command-grammar wording are all present; 0 forbidden phrases; 4 layers; the number of features in the downloaded GeoJSON = the number of gaps; a successful run has ≥ 5 analysis tool steps.
6. Determinism: two runs on the same frozen inputs produce deterministic receipts (with random DatasetRef IDs and timestamps removed) that are identical byte for byte; the audit script rerun matches; the demo HTML re-rendered from the saved ScenarioReport JSON matches byte for byte.
