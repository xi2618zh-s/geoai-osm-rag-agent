# ADR-0013: M07 uses a separate constrained plan-preview contract

- Status: Accepted
- Date: 2026-10-06
- Affected modules: M07, later M08/M09
- Versions: M07PlanRequest, PlanningResult, PlannedToolStep v1.0; the existing GeoDSL v1.0 and ToolSpec v1.0 are unchanged.

## Context

GeoDSL v1 describes semantic intent and steps but has no tool binding; the old workflow uses in-process objects and paths, and M04's AnalysisToolRegistry uses DatasetRefs. M07 needs to produce auditable dynamic plans without changing old interfaces and without handing unverified model text to an executor.

## Decision

1. Add separate, strict M07PlanRequest, PlanningResult and PlannedToolStep v1.0 contracts. A planning input must state the place, dataset-role metadata and place/analysis/output CRS explicitly; it accepts only controlled source identifiers, never paths or large data.
2. A restricted command grammar performs classification and extracts key parameters; a missing place or distance returns the existing ClarificationRequest v1.0. `resume_clarification` must match the original query and re-plans after completion; no session state is stored.
3. The agent's current public allow-list is `filter_attributes`, `buffer_features`, `nearest_features`, `features_within`, `spatial_join`, `aggregate_by_region`, and each must also be registered in AnalysisToolRegistry. `repair_geometry`, quality tools, population/GTFS tools and old workflow paths are not exposed to the M07 model.
4. A model may only return strict PlanningResult JSON through an injected proposer. Syntax/structure errors are repaired at most once; illegal semantics, tools, dependencies, parameters or budgets fail deterministically. A plan is accepted only when it agrees with the intent already extracted from the request, the tool bindings, parameters, preview and evidence. Executable Python, SQL, local file paths and unregistered tools are forbidden.
5. Static limits are 8 tool steps, 12 cost units and at most 1 declared retry per step; plans generated by M07 actually declare 0 retries and are not executed. Input types, CRS, dependency closure, forward references, reuse of output roles, parameter types and business values are all checked before the preview.
6. Add `POST /plan-preview` and `GET /plan-ui`, returning the semantic plan, tool preview, confidence and evidence. A confidence of 1.0 means an exact match of the restricted grammar; it is not statistically calibrated. `rank` is explicitly rejected because there is no deterministic registered tool for it. GTFS stop buffers are not treated as real transit isochrones.

## Compatibility and limitations

- The old `/chat`, `/workflow`, WorkflowPlan, ToolRegistry, GeoDSL, AnalysisToolRegistry and ToolSpec are unchanged; only `app_min.py` gains separate routes, and old behaviour is preserved.
- No new dependencies; the existing Pydantic, pyproj and M04 registry are reused.
- Only plan preview and static admission are done: M07 plans are not executed, and there is no M08 result validation/replanning or M09 session state. Real models, network access and large data are not part of the default offline regression.
- Restricted English commands and an explicit role catalogue are not open-domain natural-language capability. Extending the grammar, tool permissions or execution interface later requires a new version and tests.

## Evidence

- 80 v1 cases were frozen in advance; after a coverage audit, v1 was kept and 90 v2 cases were added (10 for each of the eight plannable task types, 10 rank rejections). v2 is a supplementary regression written after implementation and must not be called pre-frozen or hidden.
- M07 module tests 126/126; v2 legality, tool selection and parameter accuracy 80/80 each, rank rejection 10/10; full offline suite 361/361, compilation and existing audits pass.
